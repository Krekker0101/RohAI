# Дрон и дальний транспорт

Перезапустите `START_VIDEO_ANALYSIS.bat` и обновите страницу. Перед импортом выберите
**Дрон / дальний транспорт**. Этот режим выбран по умолчанию для новых импортов.
Для записи обычной камеры, людей и ближнего транспорта выбирайте **Обычная камера**.

Что изменилось:

- Отдельная официальная модель YOLO26s вместо быстрой YOLO26n; целостность весов
  проверяется по SHA-256 перед загрузкой. Это предобученная COCO-модель, не модель,
  дообученная на вашей записи.
- Анализ перекрывающихся участков исходного разрешения: мелкие машины меньше
  теряют детали при уменьшении входа нейросети.
- Сопоставление рамок в координатах исходного видео, устранение повторных
  обнаружений на перекрытиях и единый ByteTrack для всего кадра.
- Фильтр слишком крупных рамок: по умолчанию длинная сторона объекта не превышает
  10% короткой стороны кадра. Это ограничение масштаба для съёмки сверху, а не
  распознавание зданий; оно может отсеять крупную машину при ближней съёмке.
- Кандидаты, обрезанные внутренней границей участка, исключаются; перекрывающийся
  участок обычно позволяет увидеть объект целиком. Объекты всё ещё могут пропускаться.
- Дополнительный вариант **Дрон / дополнительно проверить повороты** анализирует
  также изображение, повёрнутое на 90°, и объединяет результаты. Он заметно медленнее.
- Показаны реальное число обработанных участков текущего кадра и прогресс,
  основанный на выполненной работе. Все кадры продолжают обрабатываться последовательно.

На CPU обработка 4K-записи может занимать десятки минут или часы. Оставшееся время
оценивается после обработки кадров. Обычный режим ограничен двумя часами, оба
режима дрона — шестью часами; отсутствие heartbeat более двух минут завершает задачу.
Проверка участков обновляет heartbeat между пакетами обработки.

## Установка и настройки

На текущем устройстве модель уже установлена. Для новой установки:

```powershell
.venv\Scripts\python.exe scripts/fetch_aerial_model.py
```

Веса загружаются из официального релиза Ultralytics или официального зеркала;
SHA-256 зафиксирован в скрипте и `configs/models/yolo26s.json`.
API импорта принимает `profile=standard`, `profile=aerial` или `profile=aerial_precise`.
Отчёт сохраняет профиль, параметры, хеш модели и число отфильтрованных кандидатов.

Настройки backend: `STA_VIDEO_AERIAL__TILE_SIZE` (по умолчанию 1024),
`STA_VIDEO_AERIAL__CONFIDENCE` (0.25), `STA_VIDEO_AERIAL__OVERLAP` (0.2),
`STA_VIDEO_AERIAL__MAX_OBJECT_FRACTION` (0.1), `STA_VIDEO_AERIAL__BATCH_SIZE` (4).
Для обученной и проверенной модели можно настроить `STA_VIDEO_AERIAL_MODEL_PATH`
и `STA_VIDEO_AERIAL_MANIFEST_PATH`; классы и хеш должны соответствовать manifest.
Изменения применяются после перезапуска backend и нового импорта.

## Дообучение

Разметки у пользователя пока нет. Веса на этой записи не обучались; результаты
самой модели нельзя выдавать за правильные ответы. Подготовлены 12 исходных кадров
в `.runtime/aerial-training-review-v1/index.html` и `review.json` со статусом
`DRAFT_UNREVIEWED`. Они нужны для дальнейшей ручной разметки машин и фоновых объектов.

Для настоящего дообучения нужны проверенные рамки и классы, отрицательные примеры
зданий/крыш, дополнительные независимые записи и подтверждённые права на обучение.
Разделение train/validation/test делают по записи/сцене, а не соседним кадрам.
В проекте уже есть проверка dataset release, training runner, evaluation и registry;
подготовленные кадры не обходят эти проверки и автоматически не публикуют модель.

Метод анализа участков описан в [руководстве Ultralytics](https://docs.ultralytics.com/guides/sahi-tiled-inference/).
Исходные веса — [официальный релиз YOLO26](https://github.com/ultralytics/assets/releases/tag/v8.4.0).
