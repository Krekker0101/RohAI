# RohAI 1.0 — руководство пользователя

## Запуск

Откройте `start-rohai.bat` в корне проекта. Нужны установленное проектное окружение Python 3.12+ (`.venv`), зависимости Vision/MAKET и заранее собранный dashboard (`npm.cmd run build` из `apps/dashboard`). Launcher запускает два локальных backend; frontend обслуживается ими как статические файлы. Отдельный Vite-сервер не требуется.

После подтверждённых health checks откроется `http://127.0.0.1:8001/maket`. DEMO доступен через ссылку в шапке, на порту 8000. Повторный запуск использует проверенный существующий workspace. Ошибки видны в терминале и `.runtime/*-backend.log`. Для завершения нажмите Ctrl+C в окне launcher и дождитесь остановки. Закрытие вкладки не останавливает сервисы.

## Разрешения

Первое сопряжение разрешает этому браузеру локальный просмотр на семь дней. Секрет находится в HttpOnly/SameSite Strict cookie, на Windows состояние защищено DPAPI текущего пользователя; секретов в frontend и localStorage нет. Сопряжение восстанавливается после перезапуска, но не даёт права изменять настройки или управлять ESP32.

Настройка и управление разрешаются отдельным подтверждением на текущий запуск, максимум до восьми часов с запуска сервера. Копирование токена не требуется. «Диагностика и приватность → Отозвать доступ браузера» отзывает сохранённый просмотр и очищает разрешения данного браузера; при действующем разрешении управления сначала вызывается безопасная остановка. После восьми часов для нового разрешения управления перезапустите launcher.

Доступ предназначен для одного браузера текущего Windows-пользователя. Новый браузер заменяет старое сопряжение. Локальный токен для CLI остаётся возможным; удалённое управление не включается.

## Подготовка и режимы

Автоподготовка проверяет камеру, модель, калибровку и ESP32. Единственная камера выбирается автоматически; при нескольких используйте «Калибровка» и выбор камеры. ESP32 определяется по USB-кандидатам и проверенному ответу firmware 1.0.1; при нескольких выберите устройство в инженерных настройках из списка. Отсутствие устройства не подменяется Mock.

| Режим | Источник данных | Исполнение |
|---|---|---|
| DEMO | Синтетический поток и треки, явно помеченные | Mock; физического исполнения нет |
| REAL VISION | Живые кадры и оценки модели | Рекомендации и виртуальный preview; ESP32 не управляется |
| PHYSICAL MAKET | Камера, подтверждённая калибровка и свежие измерения | Только после аппаратных проверок, отдельного подтверждения и локального ARM |

«Нет данных» отображается как `—`; его нельзя трактовать как нулевую очередь. COCO baseline не имеет измеренной точности на игрушечных объектах. Виртуальные сигналы обозначены PREVIEW. Фаза ESP32 показывается отдельно по ACK/readback; оставшееся время — оценка host-контроллера, а не счётчик ESP32. Электрическое ACK не доказывает свечение ламп.

## Калибровка

Закрепите камеру, нажмите «Калибровка». Автоматическая геометрия и четыре перспективных угла — гипотезы. Проверьте подъезды, полосы, очереди, stop/entry/exit lines и пешеходные зоны. Вершины можно перетаскивать или задавать координатами X/Y с клавиатуры. Для линии нужны начало, конец и точка со стороны приближения. Подтверждение сохраняет геометрию вместе с привязкой к камере и эталонным кадром.

После перемещения камеры, смены разрешения или восстановления потока управление не возобновляется автоматически. Подтвердите положение/калибровку и свежие измерения заново. Недостаток статических признаков для проверки положения сохраняет блокировку.

## Управление и запись

«Начать» запускает выбранный режим только при готовности. Физический старт требует отдельного диалога и локального ARM на ESP32. Независимую аппаратную защиту должен реально проверить специалист; checkbox в инженерной настройке сохраняет его подтверждение, не выполняет испытание.

«Пауза» и «Стоп» выполняют безопасную остановку; продолжение требует нового старта. «Аварийный стоп» вызывает тот же приоритетный безопасный путь. Это программная команда, поэтому физическая аварийная кнопка и независимая защита обязательны. «Сброс» разрешён после остановки и не запускает управление.

Метаданные записываются локально автоматически, если хватает лимита сеансов. «Записать видео» требует явного согласия; по умолчанию видео выключено. По умолчанию пределы: 20 сеансов, 512 MiB на сеанс, 30 минут записи, срок хранения 7 дней (изменяется в инженерных настройках). Истечение срока только помечает запись. При заполнении новые записи отключаются, старые сохраняются. Выбранный закрытый сеанс удаляется только после отдельного подтверждения; активный удалить нельзя.

«Записи и replay» открывает историю с последовательностью, временными метками, решениями, safety и hardware ACK. В replay доступны воспроизведение, пауза, скорость и перемотка внутри части истории; части загружаются по 200 событий. Replay не создаёт аппаратный runtime и не посылает команды. Неполная запись помечается явно.

Физическая готовность RohAI 1.0 пока **NOT VERIFIED**: выполненные программные проверки не заменяют испытания макета. См. [ограничения](REMAINING_LIMITATIONS.md).
