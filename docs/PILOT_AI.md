# Пилот AI — локальный голосовой гид RohAI

Пилот встроен в верхнюю панель Dashboard. Он отвечает на вопросы о возможностях проекта, анализе видео, дорожной маске, управлении, аналитике и ограничениях. Пилот работает только с опубликованными проверенными фактами из `configs/pilot/knowledge.json`: поиск подбирает релевантную выдержку, затем локальная модель самостоятельно формулирует ответ по её содержанию. Сервер проверяет ID источников, формат текста, язык и отсутствие неподтверждённых чисел. В диалоге показаны источники и статус реализации; это проверка происхождения, а не гарантия безошибочности генеративной модели. Он не читает текущую телеметрию и не управляет светофорами.

## Установка и запуск на ноутбуке

Из корня репозитория в PowerShell:

```powershell
uv sync --locked --extra pilot --extra vision --extra learning
.venv/Scripts/python.exe scripts/fetch_pilot_models.py
npm.cmd --prefix apps/dashboard ci
npm.cmd --prefix apps/dashboard run build
./START_VIDEO_ANALYSIS.bat
```

Модели скачиваются однократно из закреплённых версий Hugging Face. Скрипт проверяет размер и SHA-256 каждого файла. После установки текст, микрофон и речь работают локально без API-ключа. Для открытия Пилота нажмите кнопку **PILOT AI** в верхней панели. Если запущен другой frontend, используйте тот же backend и обычную панель Dashboard. Первое обращение загружает модель и может занять заметно больше времени, чем следующие.

Требуются Python 3.12+, `uv`, Node.js/npm и современный браузер с Web Audio/AudioWorklet. Микрофон браузер разрешает на `localhost` или HTTPS. Кнопка микрофона записывает одну фразу до 20 секунд; тишина завершает её автоматически. Текстовый диалог доступен без микрофона и без аудиовыхода. Языки интерфейса речи: русский и английский; таджикский не валидирован. Для небольшого CPU-ноутбука это последовательный локальный inference, поэтому ответы не мгновенные.

## Устройство

- Предпочтительная модель — `Qwen3-4B-Q4_K_M` из официального GGUF-репозитория Qwen, с Windows CPU-движком llama.cpp. Оба пакета закреплены в manifests. Проверяются SHA-256 весов и архива, а также соответствие EXE/DLL архиву перед запуском. Модель 1.5B используется только как экспериментальный резерв; 0.5B и динамический INT8 исключены из рабочего пути. Частично скачанные веса не загружаются. Название модели возвращает `/api/v1/pilot/capabilities`.
- `Whisper-base` распознаёт WAV 16 кГц, моно, PCM16. `Piper` синтезирует русскую и английскую речь потоковыми кусками. Аватар собирается из предоставленных бесшумных анимаций тела и отдельного рта на Canvas. Рот двигается по RMS действительно воспроизводимого аудио; при mute и stop воспроизведение прекращается.
- История в памяти сервера ограничена временем и количеством сессий. В браузере она живёт до закрытия вкладки и не записывается в localStorage. Аудио и текст запросов не сохраняются сервером. Сервер ограничивает частоту запросов, размер аудио и доступ: локальный адрес без токена либо настроенный viewer/operator token. `/api/v1/pilot/*` — только чтение и управление собственной сессией.
- Скрытие вкладки останавливает микрофон и озвучку, но сохраняет выполняющийся текстовый запрос. После возвращения готовый ответ остаётся в диалоге. Кнопка остановки, новый вопрос и закрытие Пилота явно отменяют текущий запрос. Ошибка сервера или таймаут отображаются как ошибка с возможностью повторить вопрос.
- Источники проходят allowlist путей и показываются вместе с SHA-256 файла и статусом `implemented`/`partial`/`experimental`/`planned`/`unconfirmed`. Статус — описательная метка, а не сертификат полевых испытаний.

## Настройка и проверка

Настройки доступны через `STA_PILOT__*`; пример в `configs/pilot.env.example`. `STA_PILOT__PROVIDER=local` установлен по умолчанию. Опционально поддерживается локальный Ollama на `127.0.0.1:11434` для выбора источников и генерации ответов; Whisper и Piper остаются локальными. Никакого облачного API Пилот не требует.

```powershell
.venv/Scripts/python.exe -m scripts.evaluate_pilot --output artifacts/pilot-ai/neural-corpus.json
.venv/Scripts/python.exe -m pytest -q tests/test_pilot_assistant.py
npm.cmd --prefix apps/dashboard run lint
npm.cmd --prefix apps/dashboard run build
```

`evaluate_pilot` запускает **настоящую** локальную модель по корпусу из 42 вопросов и сохраняет результаты. Модульные тесты используют отдельную тестовую заглушку и не являются доказательством качества нейросети. Для проверки вручную задайте вопросы «Как загрузить видео?», «Это реальная точность?», «Что означает ID?» и «Какая сейчас погода?». Последний должен быть отклонён как вопрос вне проекта. На панели проверьте остановку ответа, повтор речи, очистку истории, звук, переключение языка и разрешение микрофона.

Установщик по умолчанию загружает Qwen3 GGUF, Windows CPU-движок llama.cpp, Whisper и голоса Piper. Прерванная загрузка продолжается через Range с повторными попытками; установка атомарна и выполняется только после полной проверки SHA-256. Сеть во время диалога не нужна. При отказе валидации выполняется одна повторная генерация, затем показывается явная ошибка без подстановки готового ответа.

Подбор источника не требует отдельного нейросетевого прохода. Текстовая модель остаётся загруженной между вопросами. Озвучка выполняется отдельным лёгким процессом: остановка речи не выгружает Qwen. Первый ответ включает загрузку весов; CPU-генерация может занимать десятки секунд, особенно при одновременно работающем анализе 4K-видео.

## Ограничения

Результаты настоящей модели сохраняются в `artifacts/pilot-ai/neural-corpus-qwen3.json`. Поле `passed` проверяет результат запроса и ожидаемый источник; смысловую точность нужно оценивать по самим ответам. Эти проверки не гарантируют безошибочность ответов на любые новые вопросы.

Распознавание русской речи может ошибаться на коротких и шумных фразах; перед отправкой распознанный текст показывается в диалоге. Пилот не видит текущий видеофайл или точные показания датчиков, если они не опубликованы в проверенной базе знаний. База знаний описывает код и документацию, но не доказывает точность на дорогах, безопасность ESP32 в полевых условиях или преимущество алгоритма на реальном перекрёстке. Для этого нужны независимая разметка, отдельные испытания и внешняя приёмка.

`piper-tts==1.8.0` декларирует лицензию **GPL-3.0-or-later**. Перед распространением собранного продукта проверьте совместимость этой зависимости с выбранной лицензией RohAI и требования к исходному коду; для закрытой поставки может потребоваться замена TTS-компонента.

## Анимации тела и рот

Использованы предоставленные файлы: `a84035bc66311f1bfa7e281d0d9e43b.mp4` — слушает, `e09a7eec66411f1b16fcab78a9f2435.mp4` — думает, `e082a56c66411f1a1bed6336b8c6e7b.mp4` — объясняет. Подготовленные файлы находятся в `apps/dashboard/public/pilot/`; каждый содержит только видеодорожку. Финальная заставка исключена, водяной знак исходных роликов сохранён. Прямой и обратный проходы образуют непрерывный цикл; переход между состояниями занимает 280 мс. Исходные движения рта нейтрализованы, а его покадровая геометрия хранится в `animations.json`.

Рот рисуется отдельным слоем после видео тела. Его открытие зависит только от уровня фактически воспроизводимого PCM из Web Audio AnalyserNode. При паузе, mute, stop, скрытии вкладки и между фрагментами аудио рот закрывается. Это синхронизация по амплитуде, без выдуманных фонем и без предварительно записанной речи. В режиме reduced motion тело остаётся неподвижным; аудиосинхронизация рта сохраняется.

Для повторной подготовки этих конкретных роликов нужен FFmpeg и Vision-зависимости. Можно установить только инструмент обработки `uv pip install --python .venv/Scripts/python.exe imageio-ffmpeg==0.6.0`, затем вызвать `scripts/prepare_pilot_animations.py --listening PATH1 --thinking PATH2 --explaining PATH3`. Скрипт рассчитан на геометрию предоставленных роликов, а не на произвольных персонажей. FFmpeg не требуется при работе приложения: подготовленные ресурсы уже включены в Dashboard.

Официальные источники пакетов: [Qwen3 GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF), [llama.cpp b11588](https://github.com/ggml-org/llama.cpp/releases/tag/b11588).

## Приёмка на этом ноутбуке

Qwen3-4B GGUF установлена и проверена по закреплённому SHA-256. Итог: 42/42 проверочных вопроса (34 нейросетевых ответа и 8 граничных случаев), 609 программных тестов и 11 сценариев Edge. Восемь аппаратных тестов пропущены: ESP32 отсутствует. Нативный Piper выдал PCM 22050 Гц на RU/EN; остановка речи сохранила загруженный процесс Qwen. Медианная задержка нейросетевого ответа — 8.78 с в этом прогоне.

Сводка и границы проверки: `artifacts/pilot-ai/readiness.json`. Эти результаты подтверждают проверенный сценарий демонстрации локального гида; они не измеряют качество дорожного детектора и не гарантируют правильность любого нового вопроса. После обновления перезапустите `START_VIDEO_ANALYSIS.bat` и обновите страницу через Ctrl+F5.
