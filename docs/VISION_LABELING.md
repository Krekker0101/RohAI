# Проверка распознавания на собственных видео

Для первого ролика уже подготовлены 12 исходных 4K-кадров:
`artifacts/realtime-video-review/annotate.html`. Откройте файл в Edge/Chrome.
Этот инструмент работает локально, без сервера и отправки видео в облако.

1. Обведите видимые машины рамками; для остальных объектов выберите класс.
   Не отмечайте здания как автомобили. Для маленьких объектов используйте ползунок
   «Масштаб» и прокрутку кадра. Координаты сохраняются в исходном 4K-разрешении.
2. Укажите имя/идентификатор проверяющего. Подтвердите кадр только после проверки
   всех классов в списке. Пустой кадр тоже требует явного подтверждения.
3. Переключайтесь между кадрами. Удаление/добавление рамки сбрасывает подтверждение.
4. Нажмите «Сохранить JSON разметки». Перед закрытием всегда экспортируйте JSON.
   Для продолжения выберите сохранённый файл через «Продолжить из JSON».

Проверка и преобразование в нативную схему проекта:

```powershell
.venv\Scripts\python.exe scripts/import_review_labels.py artifacts/realtime-video-review C:\Users\hp\Downloads\human-labels.json --output datasets/reviews/first-road-labels
```

Выходная папка должна быть новой. Несовместимые видео, изменённые кадры,
невалидные рамки и отсутствие проверяющего отклоняются до создания результата.
Неподтверждённые кадры не экспортируются как отрицательные примеры.

Для других видео:

```powershell
.venv\Scripts\python.exe scripts/prepare_video_review.py "путь-к-видео.mp4" --output artifacts/another-review --count 24
```

Классы редактора: 0 car, 1 bus, 2 truck, 3 motorcycle, 4 bicycle, 5 pedestrian.
Это локальная схема разметки, не номера COCO; перед обучением необходимо явно
сопоставить её с class_mapping набора данных. Не подменяйте классы модели.

12 разрозненных кадров подходят для первичной проверки детекции, но не измеряют
качество tracking/ожидания/очередей. Для этого нужны непрерывные последовательности
и отдельные метки событий. Весь один ролик/сеанс должен оставаться в одном split.
Для независимой оценки нужны другие записи; права и условия съёмки в DatasetSpec
заполняются по фактическим данным. Импорт рамок ещё не создаёт DatasetRelease
и не запускает обучение.

## Измерение распознавания

Без разметки можно измерить время детектора и сохранить предсказания:

```powershell
.venv\Scripts\python.exe -m scripts.evaluate_review artifacts/realtime-video-review --output artifacts/another-detector-run
```

После импорта человеческих рамок:

```powershell
.venv\Scripts\python.exe -m scripts.evaluate_review artifacts/realtime-video-review --labels datasets/reviews/first-road-labels --output artifacts/first-reviewed-evaluation --confidence 0.25
```

Выходная папка должна быть новой. Отчёт содержит TP/FP/FN, precision/recall, AP,
матрицу классов и отдельную группу маленьких объектов (площадь рамки <1024 px²
в исходном изображении). Размер объекта — не измеренная дистанция до камеры.
Перепутанные классы COCO преобразуются через manifest модели в локальную схему.
Без человеческих меток quality.status остаётся UNSCORED; наблюдение предсказаний
не превращается в доказательство качества. Оценка на этих кадрах диагностическая,
а не независимая приёмка.

Первый запуск сохранён в `artifacts/realtime-detector-baseline/report.json`:
12 исходных 4K-кадров, CPU, YOLO26n, input 640, два потока Torch;
прогретый predict p50 около 50.4 мс, p95 около 98.2 мс. Декодирование,
трекинг, аналитика, камера и светофоры в эту задержку не входят.
Доказательства точности пока отсутствуют. 22 связанных теста прошли.

Проверки реализации: 40 Python-тестов (включая существующие dataset contracts),
два Edge-сценария редактора, Ruff и JS syntax. Браузерные тестовые рамки обозначены
AUTOMATED_UI_FIXTURE_NOT_GROUND_TRUTH и не используются как реальные метки.

## Дальние автомобили на исходном 4K-видео

При пороге 0.25 обычный YOLO26n на 12 целых кадрах не сохранил ни одного
кандидата автомобиля. Проверка уже существующего режима нарезки кадров:

```powershell
.venv\Scripts\python.exe -m scripts.compare_aerial_detector artifacts/realtime-video-review --output artifacts/realtime-detector-baseline/aerial-s-3frames.json --count 3
```

YOLO26s с фрагментами 1024 px и перекрытием 20% нашёл 3, 4 и 5 кандидатов
на первых трёх кадрах. При двух потоках Torch повторный замер вызова детектора
занял 2368, 2348 и 2422 мс на кадр; при шести потоках — 2143, 2121 и 2101 мс
с теми же рамками на этих кадрах. Видеомодуль уже выбирает до шести потоков по
умолчанию для aerial-профиля. Увеличение фрагментов до 1536 px сократило время
до 879, 914 и 843 мс, но оставило лишь 1, 1 и 4 кандидата, поэтому этот режим
не включён автоматически. Это диагностическое сравнение, **не** измерение
precision/recall или доказательство, что все кандидаты являются автомобилями.
Режим нарезки доступен для импортированного видео; автоматически включать его
в живой контур нельзя из-за измеренной задержки и отсутствия проверки точности.

Полный замер на 12 выбранных кадрах сохранён в
`artifacts/realtime-detector-baseline/aerial-s-12frames.json`: 45 предложений,
среднее время детектора 2285 мс/кадр, SHA256 весов записан в отчёт. Их можно
просмотреть отдельно от человеческой разметки, открыв
`artifacts/realtime-video-review/proposals.html`. Чтобы повторно построить страницу:

```powershell
.venv\Scripts\python.exe -m scripts.render_detector_proposals artifacts/realtime-video-review artifacts/realtime-detector-baseline/aerial-s-12frames.json --output artifacts/realtime-video-review/proposals.html
```

Предложения модели никогда не импортируются в файл меток человека.
