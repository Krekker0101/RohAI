# Анализ загруженного видео

Запустите `START_VIDEO_ANALYSIS.bat`. Откроется вкладка **Анализ видео**.
Выберите запись и нажмите **Загрузить и анализировать**. Камера и ESP32 не нужны.
Для съёмки сверху выбран режим **Дрон / дальний транспорт**; для обычной камеры
и людей переключите **Режим распознавания**. Подробнее: [AERIAL_VIDEO.md](AERIAL_VIDEO.md).
Если порт 8000 занят, остановите прежний запуск или используйте:

```powershell
.venv\Scripts\python.exe -m smart_traffic_backend.video_cli --port 8010
```

Для первой установки:

```powershell
uv sync --locked --extra dev --extra vision --extra learning
uv run --extra vision python scripts/fetch_vision_demo.py
uv run --extra vision python scripts/fetch_aerial_model.py
uv sync --locked --all-extras
uv run --all-extras python scripts/fetch_road_model.py
cd apps/dashboard
npm ci
npm run build
cd ../..
```

## Что отображается

- Загрузка файла: фактически переданные байты.
- Проверка записи, загрузка модели, обработка кадров, создание отчёта.
- Доля обработанных кадров, скорость обработки и приблизительное оставшееся время.
- Последний обработанный кадр с рамками, уверенностью модели, ID и траекториями.
- Объекты текущего кадра, число уникальных треков и временной ряд наблюдений.
- История, отмена, удаление завершённых задач и JSON-отчёт.
- **Режим презентации**: увеличенное превью и результаты без формы импорта.

Нейросеть выполняет обнаружение; ByteTrack сопоставляет объекты между кадрами.
Панель показывает вычисленные наблюдения и этапы, а не выдуманные мысли модели.
Нулевая детекция допустима и отображается без искусственных объектов.

Обрабатываются все кадры последовательно, без ожидания скорости воспроизведения
и без пропуска кадров ради FPS. Превью обновляется максимум дважды в секунду;
между обновлениями интерфейса нейросеть продолжает обработку. Тяжёлая обработка
работает в отдельном завершаемом процессе и не открывает устройства.

## Ограничения и хранение

По умолчанию: файл до 256 МБ, запись до 30 минут, до 100 000 кадров,
разрешение до 3840 × 2160, десять задач в истории, один активный анализ.
Поддержаны MP4, MOV, AVI, MKV, WEBM и M4V, если установленный OpenCV декодирует кодек.
Настройки: `STA_VIDEO_MAX_UPLOAD_MB`, `STA_VIDEO_MAX_DURATION_SECONDS`,
`STA_VIDEO_MAX_FRAMES`, `STA_VIDEO_MAX_JOBS`, `STA_VIDEO_JOBS_DIRECTORY`.
Хранилище ограничено бюджетом; для освобождения места удалите завершённые задачи.

Файлы находятся в `.runtime/video-analysis/<job-id>/`: запись, `preview.jpg`,
`status.json`, итоговый `report.json`, покадровый `frames.jsonl`.
Покадровый журнал ограничен 64 МБ; число пропущенных записей явно указано в отчёте.
Это ограничение журнала не пропускает кадры анализа. Полный временной ряд
сохраняется в отчёте; панель показывает последние 120 точек.
После перезапуска незавершённая задача получает ошибку, а не ложный успех.
При отмене/выходе дочерний процесс останавливается; отчёт доступен только после успеха.
На Windows превью читается в память с закрытием файла до отправки ответа браузеру.
Кратковременная блокировка файла обрабатывается повторными попытками; если картинка
всё ещё занята, сохраняется предыдущая и анализ продолжается. Число таких обновлений
отражено в отчёте как `preview_skipped_updates`. Исключения анализатора также выводятся
в консоль с ID задачи и traceback.

Локальный запуск слушает только `127.0.0.1`. При настроенном `STA_OPERATOR_TOKEN`
введите его в **Подключение**; все видеоэндпоинты требуют этот токен.
Без токена допускаются только локальные клиенты и разрешённый Origin.
Используйте один процесс backend (`--workers 1`); несколько процессов не делят
очередь и не поддерживаются этим локальным режимом.

Уверенность модели не равна измеренной точности. Число треков не является
измеренным транспортным потоком, движение в пикселях не является дорожной скоростью,
малое движение не доказывает очередь. Время записи вычисляется по индексу кадра/FPS;
для переменного FPS это номинальная шкала. Качество на конкретной сцене требует
независимой разметки и, при необходимости, обучения подходящей модели.

## Воспроизводимая проверка

```powershell
.venv\Scripts\python.exe scripts/run_video_acceptance.py
```

Проверка использует локальный ролик `recordings/person-bicycle-car-detection.mp4`
(24 кадра начиная с 48-го), настоящий YOLO26 + ByteTrack, изолированный сервер
и браузер Edge. Параметры: `--source`, `--start-frame`, `--frames`, `--output`.
Проверяются импорт через UI, все кадры, детекции, хеш модели, превью, 100% и
скачивание отчёта; отдельные браузерные фикстуры проверяют отмену и ошибку.
Артефакты: `acceptance.json`, `browser-report.json`, `presentation.png`, `mobile.png`.
Это проверка работоспособности, а не независимая оценка точности или пользы на дороге.
