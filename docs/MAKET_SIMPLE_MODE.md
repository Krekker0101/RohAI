# RohAI Simple Mode

## Запуск

Из корня проекта:

```powershell
.venv/Scripts/python.exe -m traffic_vision.cli maket start --open
```

Или `rohai maket`, если окружение активировано. В интерактивном терминале браузер
открывается по умолчанию; `--no-open` отключает это. Двойной щелчок по
`start-rohai.bat` запускает то же окружение и открывает браузер.
Зависимости: `uv sync --extra vision`; для CAMERA_ONLY pyserial/PlatformIO не нужны.

## Первый запуск

1. **Камера.** Dashboard входит через локальную сессию и запускает discovery.
   Единственная камера с рабочим кадром выбирается и сохраняется автоматически.
   Несколько камер показываются с миниатюрами; требуется один выбор.
   Название устройства может отсутствовать — интерфейс не выдумывает его.
2. **Дороги.** Направьте закреплённую камеру на макет. Нажмите «Предложить по
   изображению» либо редактируйте зоны и линии непосредственно на кадре.
   Выберите направление и разметку; перетаскивайте вершины или нарисуйте заново.
   Линия требует начала, конца и точки со стороны приближения.
   Проверьте каждый подъезд, полосу, очередь, линии входа/выхода и пешеходные зоны.
   Подтверждение оператора обязательно. JSON вводить не нужно.
3. **Готово.** После проверки source, resolution, alignment и свежих измерений
   появляется SYSTEM READY. Нажмите «НАЧАТЬ»: запускается SHADOW controller.

Простая разметка — кандидат для четырёх подъездов. Image-assisted detector использует
Canny/Hough и поддерживает только различимые горизонтальные/вертикальные границы.
Он может принять другие контрастные линии за дороги. Заполненные по шаблону
полосы, entry/exit и пешеходные зоны являются **непроверенными предложениями**;
совпадающие зоны/линии необходимо исправить вручную. Кнопка подтверждения не
является измерением точности. Для сложной геометрии используйте Engineer Mode.

## Повторный запуск

Camera/settings и calibration/reference сохраняются backend в настроенных путях.
Preview и vision pipeline открываются при запуске выбранной камеры. Сохранённая
калибровка используется только при совпадении source, resolution и свежем
подтверждении положения относительно reference. Недостаток статических признаков
также блокирует старт: неизменность позы не угадывается.
При совместимом профиле требуется только «НАЧАТЬ». Controller не запускается сам.
После сбоя или reconnect требуется явная проверка/калибровка и новый Start.

Overlay preferences, последний UI mode и presentation preference сохраняются
в localStorage без секретов. CAMERA_ONLY/SHADOW/COCO_BASELINE/BALANCED — defaults
поставляемого config; настройки Engineer не перезаписываются при открытии Simple.

## Экран и режимы

`/maket`: большая камера, измеренные очереди/ожидание, рекомендации, виртуальные
сигналы и одна кнопка Start/Stop. Неизвестные или несвежие измерения показываются
как `—`; проценты улучшения не генерируются. Среднее ожидание — взвешенное по
наблюдаемому числу автомобилей. «Проехали» — события пересечения stop line за 60 с.
Для learned policy показаны входы/выходы, без выдуманного объяснения решения.

Presentation включает отдельную компоновку и запрашивает fullscreen; если браузер
отказывает, компоновка остаётся доступной. Engineer controls скрыты.
Виртуальные лампы показывают snapshot SafetySupervisor, а не proposed action.
Они не подтверждают физическое свечение. При остановке/неизвестном состоянии
лампы не показывают придуманную фазу.

`/maket/engineer`: прежние token diagnostics, Serial/ESP32, модели, raw geometry,
preflight, запись, overlays и hardware tests сохранены. Physical Output включается
только там и требует прежних hardware/safety/arming проверок. Simple Start не
отправляет `start`, `manual`, ACTIVE или физические команды.

## Локальная сессия

CLI разрешает автоматическую сессию только для listener `127.0.0.1`. Browser делает
same-origin POST `/api/maket/session`. Проверяются peer IP, точный Host, Origin и
Sec-Fetch-Site. Backend выдаёт процессную случайную HttpOnly/SameSite=Strict cookie,
действующую максимум 8 часов и ограниченную `/api/maket`. Cookie перестаёт работать
после перезапуска. Секрет не передаётся в URL, HTML, localStorage или CLI output.
Bootstrap bearer credential не используется, поэтому обменивать/сохранять его не нужно.

HTTP loopback cookie не имеет Secure flag; сервер не предназначен для публикации
или reverse proxy. Локальные процессы входят в доверенную границу. Прямой вызов
factory по умолчанию не включает local sessions; explicit operator token остаётся
обязательным. Для внешнего доступа нужна отдельная TLS/auth архитектура — данный
режим её не заменяет. Чужой Origin/Host не получает cookie или cookie-based API access.
